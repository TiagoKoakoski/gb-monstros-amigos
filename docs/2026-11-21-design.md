# Monstros Amigos (Game Boy) — design

## Intenção
Refazer no GB Studio 4.3.2 o jogo "Monstros Amigos" que já existe em Godot
(`~/Projetos/jogos/monstros-amigos`), para dois objetivos:
1. Experimentar o GB Studio com um jogo cujo design já está validado.
2. Ter uma versão retrô que o filho de 5 anos possa jogar na TV, com controle.

## Objetivos
- Mesmo jogo: jardim com 4 monstros (Drácula, Frankenstein, Múmia, Lobisomem).
  Cada um perdeu uma coisa: morceguinho de pelúcia, flor, rolo de faixa, bola.
- Um balão acima de cada monstro mostra o **desenho** do item que ele quer.
- Pega e entrega só encostando. Carrega um item por vez.
- Item levado ao monstro errado: nada se perde, o monstro só "nega" (balanço/emote).
- Parado ~5 s sem progresso: um vaga-lume aparece e voa até o próximo objetivo.
- Os quatro ajudados: festa (monstros dançam, música/efeito) e qualquer botão recomeça.

## Não-objetivos
- Fases extras, voz, save, menus.

## Anti-objetivos (fracasso mesmo funcionando)
- Qualquer texto necessário para jogar.
- Inimigos, tempo, game over, susto.
- Arte ou som de terceiros.

## Restrições
- Game Boy: 160x144, 4 tons, blocos 8x8, sprites 8x16/16x16, poucos sprites por linha.
- Jardim maior que a tela (~2x2 telas) com rolagem, para dar o que explorar.
- Jogar na TV: export web do GB Studio (navegador, aceita controle) ou ROM em emulador.

## Abordagens consideradas
1. **Arte própria + projeto gerado por script (ESCOLHIDA).** Sprites e cenário em
   4 tons gerados em Python; cenas, atores e eventos escritos direto nos arquivos
   `.gbsres` a partir do template `blank`. O usuário abre no GB Studio e aperta Play.
2. Partir do projeto de exemplo do GB Studio: rápido, mas visual genérico e assets de terceiros.
3. Só esqueleto + guiar o usuário na interface: ensina mais, porém bem mais lento.

## Decisões do usuário
- Abordagem 1. Fazer este primeiro; depois um roguelike "dungeon crawler" (design separado).

## Fica a cargo de quem constrói
- Tipo de cena (top-down), tamanhos exatos de sprite, posições no mapa.
- Como implementar balão/vaga-lume com os eventos do GB Studio (atores auxiliares, variáveis).
- Música/efeitos: criados do zero (sem amostras de terceiros).
- Verificação: tentar compilar sem interface (CLI do GB Studio a partir do código-fonte
  v4.3.2) e rodar a ROM num emulador para capturar telas; se não der, validar abrindo
  no GB Studio.
